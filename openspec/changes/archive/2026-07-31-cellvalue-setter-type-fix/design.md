## Design: CellValue setter type fix

### Problem

`Partial<CellValue>` distributes over the discriminated union, creating a type hole where
cross-variant field combinations pass TypeScript type-checking. The old flat interface
didn't have this issue because `Partial` on an interface just makes every field optional
without changing variance.

### Solution

Replace `Partial<CellValue>` in the setter signature with a `CellValueInput` union of
optional-discriminant variant shapes. Verified empirically: a flat all-optional
interface CANNOT reject cross-variant leakage (`{ valueType: "Number", string: "x" }`
compiles), while the union form rejects it via excess-property checking (TS2353) and
still accepts shape-inference objects (`{ formula: "..." }`, `{ hyperlink, hyperlinkText }`,
`{ richText: [...] }`, `{ number: 42 }`) and explicit variants.

```
Before:
  set value(val: CellValue | Partial<CellValue> | string | number | boolean | Date | null)

After:
  set value(val: CellValueInput | string | number | boolean | Date | null)
```

`CellValue` is dropped from the union: every `CellValue` member is assignable to the
corresponding `CellValueInput` member (required fields satisfy the optional-discriminant
form), so it is redundant.

Side effect (intended): `{ valueType: "Number" }` without `number` no longer compiles —
the variant field is required when the discriminant is present. This matches the runtime,
which also rejects `CellValue` objects missing required fields. Old flat interface leaked
cross-variant fields too (all-optional), so this is strictly tightening, not a regression.

### Changes

**`scripts/apply-glue.cjs`** — two edits:

1. New constant `CELLVALUE_INPUT_TYPE` (same maintenance surface as `CELLVALUE_UNION_TYPE`):

```typescript
const CELLVALUE_INPUT_TYPE = `export type CellValueInput =
  | { valueType?: "Null" }
  | { valueType?: "Number"; number: number }
  | { valueType?: "String"; string: string }
  | { valueType?: "Boolean"; boolean: boolean }
  | { valueType?: "Date"; dateSerial: number }
  | { valueType?: "Formula"; formula: string }
  | { valueType?: "Error"; errorValue: string }
  | { valueType?: "Hyperlink"; hyperlink: string; hyperlinkText?: string }
  | { valueType?: "RichText"; richText: Array<RichTextRun> }
  | { valueType?: "Merge" };`
```

1. Update `REFINED_CELL_VALUE_SETTER` to reference `CellValueInput` instead of `Partial<CellValue>`.

2. Inject `CELLVALUE_INPUT_TYPE` into `index.d.ts` and `native.d.ts` when they contain
   `export type CellValue =` (the DTS transform already swaps in the union; append the
   input type after it).

**`index.d.ts` / `native.d.ts`** — regenerated by `napi build --pipe`. No manual edits.

**`__test__/cell.test.ts`** — add two missing tests:

- `cell.richText` returns `null` for a Number cell
- `cell.valueOf` returns `{ valueType: "Null" }` for a freshly constructed cell

### Non-changes

- No Rust code changes
- No regex changes for the setter signature injection — the existing
  `set value(val: unknown)` regex match still fires, `REFINED_CELL_VALUE_SETTER` is just
  updated text
- No changes to `dts-header.d.ts` — `CellValueInput` references `CellValue["valueType"]`
  which resolves from the `CellValue` union injected earlier in the same file during
  the `napi build` pipeline
