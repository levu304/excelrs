## Why

`v2.5.0` (change `2026-07-29-cell-value-getter-primitives`) shipped primitive unwrapping for `Cell.value` — `Number`/`String`/`Boolean`/`Date`/`Null` cells now return the underlying JS primitive, and a new `Cell.type` discriminant accessor was added. The proposal and spec for that change also claimed: *"The TypeScript `CellValue` interface becomes a proper discriminated union (`CellValueResult`) so `cell.value` narrows correctly"*, with a scenario asserting `if (cell.type === "Number") { const n: number = cell.value; }` compiles without a cast.

Neither claim was actually delivered:

1. **`CellValue` is still a flat `#[napi(object)]` interface**, not a discriminated union. All variant fields (`number?`, `string?`, `richText?`, `formula?`, …) are optional on the same type. The only thing that changed is `value_type` got a `#[napi(ts_type = "...")]` string-literal union — the discriminant string, not a union of variant shapes.
2. **The narrowing scenario is impossible in TypeScript.** A class getter's return type cannot be narrowed by a *separate* instance property (`cell.type`). `cell.value` has a fixed return type (`CellValueResult`); checking `cell.type` does nothing to it. No mechanism in TS can make `cell.type === "Number"` imply `cell.value: number`.
3. **Rich-type reads still require a cast.** Reading a RichText/Formula/Hyperlink/Error cell returns the flat `CellValue` object, so accessing `.richText` / `.formula` / `.hyperlink` needs `cell.value as CellValue` (or `as import('../index').CellValue` in tests). The v2.5.0 test suite does exactly this cast on every rich-type read.

This change finishes the type-safety promise v2.5.0 made: makes `CellValue` a *real* discriminated union (narrowable on `valueType`), adds `cell.valueOf()` for the full typed object, and adds a dedicated `cell.richText` accessor that mirrors the existing `cell.formula` / `cell.note` / `cell.comment` pattern — so rich-text reads need no cast at all.

## Changes

- **BREAKING (TS type only)** Replace the flat `CellValue` interface with a proper discriminated union where each `valueType` branch carries its own required fields:
  - `{ valueType: "Null" }`
  - `{ valueType: "Number"; number: number }`
  - `{ valueType: "String"; string: string }`
  - `{ valueType: "Boolean"; boolean: boolean }`
  - `{ valueType: "Date"; dateSerial: number }`
  - `{ valueType: "Formula"; formula: string }`
  - `{ valueType: "Error"; errorValue: string }`
  - `{ valueType: "Hyperlink"; hyperlink: string; hyperlinkText?: string }`
  - `{ valueType: "RichText"; richText: RichTextRun[] }`
  - `{ valueType: "Merge" }`
  This is a generated-`.d.ts` transformation only — the Rust `CellValue` struct and its runtime serialization are unchanged. Runtime objects already match these branches (extra `null` fields are allowed).
- **NEW** `Cell.valueOf()` method returns the full `CellValue` (the discriminated union). Mirrors the Rust `value_raw()` internal but is public and typed. Usage:

  ```typescript
  const cv = cell.valueOf();
  if (cv.valueType === "RichText") {
    cv.richText; // ✅ RichTextRun[] — narrowed by TS
  }
  ```

- **NEW** `Cell.richText` getter returns `RichTextRun[] | null` directly (null when the cell is not a RichText cell). Mirrors the existing `cell.formula` / `cell.note` / `cell.comment` accessors. No cast needed:

  ```typescript
  if (cell.type === "RichText") {
    const runs = cell.richText; // RichTextRun[] | null
  }
  ```

- **Spec fix** Correct the impossible requirement in `cell-value-getter/spec.md` ("narrowing via `cell.type`") with the achievable mechanism: narrow via `cell.valueOf().valueType` or use the dedicated `cell.richText` accessor.

## Capabilities

### Modified Capabilities

- `cell-value-getter`: Extend the `Cell.value` getter contract with the post-read typed access path. `CellValue` becomes a discriminated union; `cell.valueOf()` and `cell.richText` are added as narrowable accessors. The existing primitive-unwrapping behavior (v2.5.0) is retained and unchanged.
- `rich-text`: Add a requirement that `Cell.richText` returns the parsed runs directly (no cast), consistent with `cell.formula`.

### New Capabilities

- None. This change finishes work already scoped in v2.5.0; it introduces no new feature area.

## Impact

- **APIs**: `Cell.valueOf()` — NEW. `Cell.richText` — NEW. `Cell.value` getter return type — unchanged at runtime (`CellValueResult`); the *shape* of `CellValue` inside that union becomes a discriminated union (TS only). `Cell.type` — unchanged.
- **Code**: `src/model/cell.rs` (add `value_of()` + `rich_text()` getters). `scripts/apply-glue.cjs` (post-process generated `native.d.ts`: replace the flat `CellValue` interface with the discriminated union `type CellValue = ...`). `index.d.ts` / `native.d.ts` regenerated by build. No Rust struct changes.
- **Tests**: `__test__/rich-text.test.ts` updated to drop the `as CellValue` cast (use `cell.richText` or `cell.valueOf()`). Add a narrowing test asserting `if (cv.valueType === "RichText") cv.richText` compiles without cast. `__test__/cell.test.ts` gains `valueOf` / `richText` assertions.
- **Versioning**: Ship as a **patch or minor** bump (TS-only type change; no runtime behavior change for the `value` getter). If treated as breaking for downstream type-narrowing code that relied on the flat shape, bump minor and note in changelog. Recommended: `v2.5.1` (patch) since runtime is identical.
- **Dependencies**: None. Reuses the existing `dtsHeaderFile` + `apply-glue.cjs` pipeline.
