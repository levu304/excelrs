## Why

`Worksheet.setColumns(cols: any)` has zero type safety — callers get no autocomplete, no compile-time validation, and discover shape errors only at runtime via serde parse failures. The `Column` class is fully typed (header, key, width, style, etc.) but disconnected from the input path. Every other input type in the codebase (`AddWorksheetOptions`, `DataValidation`, `ConditionalFormat`, `PageSetup`) uses `#[napi(object)]` to generate typed TS interfaces. `setColumns` is the outlier.

## What Changes

- **New `ColumnInput` struct**: `#[napi(object)]` with all-`Option` fields — mirrors the plain-JS-object shape callers already pass
- **`setColumns` signature**: `cols: any` → `cols: ColumnInput[]` (TS) / `Vec<ColumnInput>` (Rust)
- **Internal conversion**: `ColumnInput[]` validated and converted to `Vec<Column>` inside `set_columns`, preserving existing logic (col_num auto-assignment, duplicate detection, style validation)
- **Existing `Column` class**: Unchanged — still has getter/setter API, still returned from column getters
- **Generated types**: `native.d.ts` and `index.d.ts` emit `ColumnInput[]` instead of `any`

## Capabilities

### New Capabilities

- `column-input-type`: Type-safe column definition input — `ColumnInput` interface with optional fields for header, key, width, colNum, hidden, style, outlineLevel

### Modified Capabilities

- _(none — this is additive type safety, no spec-level behavior change)_

## Impact

- **Rust**: `src/model/worksheet.rs` — change `set_columns` signature; `src/model/column.rs` — add `ColumnInput` struct
- **TypeScript**: `native.d.ts` / `index.d.ts` — `setColumns` type changes from `any` to `ColumnInput[]`; new `ColumnInput` interface generated by napi-rs
- **Tests**: Rust unit tests for `set_columns` with typed input; JS integration tests confirming TS compilation
- **No runtime behavior change**: Validations, col_num auto-assignment, error messages all identical. Just the type at the boundary.
